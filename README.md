# AI 模拟面试 · 多 Agent 编排

> **⚠️ 当前状态：测试中 · 未完工**
>
> 代码可运行、可打包，但尚未经过真实 API 的端到端验证。功能、接口、数据结构都可能变动，暂不建议用于正式场景。欢迎试用与反馈。

一款本地运行的桌面版 AI 模拟面试系统。全双工语音对话，面试官可被打断、也会主动打断你；面试结束后给出多维评分、逐字稿批注、满分答案重构与专项提升方案。

## 为什么做这个

市面上多数 AI 面试工具的问题是**面试官会跑偏**——聊几轮就忘了自己是谁、忘了在考什么，或者一路顺着候选人的话走，问不出深度。

根因在于把实时语音模型当成了大脑。实时模型有硬性上下文限制（音频历史通常只保留百轮/几百秒），一场 30 分钟以上的面试必然被截断，人格漂移是**必然**而非偶然。

本项目的做法是**双环架构**：

```
Fast Loop（口）    实时语音模型：只负责听懂 + 用人设语气说出导演给的意图
                  ↑ 有界、短、不依赖长期记忆

Slow Loop（脑）    后端权威状态机 InterviewState：
                  当前考察维度 / 已问题目 / JD 技能覆盖度 / STAR 完整度 /
                  追问深度 / 打断额度 / 技能深度阶梯 / 漂移分数
                  ↑ 单一事实来源，每轮落盘 SQLite，崩溃可恢复
```

人格不是"被记住"的，而是**每轮重新注入**的。所以在架构上不存在"忘了自己是谁"。

## 核心设计

### 题库约束出题

面试前由 JD + 简历生成结构化题库（技能点、领域、深度等级、来源、关联项目、预设追问路径）。导演**只能从题库中选题**，不能自由生成。这保证了每个问题都对得上 JD 要求和你的真实项目经历。

### 确定性深度阶梯

答得好不好由导演评估，但**推进方向由确定性代码决定**，不交给模型：

| 回答质量 | 动作 |
| --- | --- |
| ≥ 0.65 | 深入一层（概念 → 实践 → 细节 → 极限） |
| 0.40 – 0.65 | 同层换角度再追一次 |
| < 0.40（连续两次） | 放弃深挖、换领域，并在复盘中记低分 |

这复刻了真实面试官的行为：你确实答不上来，面试官不会一直折磨你，但分数会体现出来。

### 硬时间闸门

10 / 20 / 30 / 45 分钟四档预设。到点**强制进入收尾**，不给模型自由裁量的机会。不足 5 分钟不生成完整复盘。

### 人设契约（Persona Contract）

面试官人设是结构化 JSON 而非自由文本提示词——中英夹杂比例、打断倾向、攻击性、发散强度、追问深度、项目侧重、禁忌话题等 17 个维度可调，可校验、可版本化、可分享。

内置 11 个人设，覆盖大厂 / 中厂 / 创业 / 制造业 / 国企 / 外企 / 金融等公司画像。公司画像会同时影响出题倾向、评分权重与 JD 生成风格。

### 三层记忆

| 层级 | 内容 | 生命周期 |
| --- | --- | --- |
| 一次性 | 守卫检测、提词、STAR 判定、代码追问 | 单次调用后丢弃 |
| 会话级 | InterviewState、逐字稿、题目记录 | 落盘 SQLite，永不丢失 |
| 跨会话 | 错题本、成长轨迹、岗位库、简历库 | 长期累积 |

### 防漂移三道防线

1. **人设契约** — 结构化定义编译成运行时指令
2. **输出守卫** — 正则前置 + 小模型复核，拦截"作为 AI 助手""我无法提供"这类越界
3. **心跳重锚** — 每 N 轮或漂移抬头时，强制重灌人设与状态摘要

另外在协议层收回了发言授权：服务端 VAD 默认会自动生成回复，那会绕过导演让模型自由发言。本项目关闭了自动回复，未授权的回复会被立即取消。

## 功能

**面试前**

- 简历（PDF / DOCX / TXT）与 JD 上传解析
- 技能差距诊断：指出盲区，并给出弥补话术（"强调你的 Docker 经验来弥补 K8s 短板"）
- 只有岗位名称也行：按公司类型 + 级别一键生成贴合市场的 JD
- 人设工坊：结构化滑块调参，实时预览编译后的人格指令

**面试中**

- 全双工语音：随时打断面试官；啰嗦时面试官会主动打断你
- 回声门控：扬声器模式下用互相关检测抑制回流，避免面试官自己打断自己（仍建议戴耳机）
- STAR 引导：行为题回答缺环节时主动追问"能具体讲讲当时的 Action 吗"
- 实时提词器（Copilot）：卡壳时给关键词与展开方向；沉默超时会自动提示
- 代码沙盒：语法高亮编辑器，边写边语音沟通思路
- 动态追问与边界测试："并发量提升十倍会出什么问题""能优化到 O(1) 吗"
- 视频会议式布局 + 本地摄像头自视图（视频不上传）

**面试后**

- 多维雷达图：技术深度、逻辑表达、抗压能力、价值观匹配等
- 逐字稿高亮批注：标出表现好与差的具体位置
- 满分答案重构：结合你的真实经历，给出"这么说就能拿满分"的示范
- 韵律分析：语速、停顿占比、填充词频率、被打断次数（规则计算，不靠 LLM 猜）
- 专项提升方案：针对放弃深挖的技能点给出训练动作与下次模拟配置建议
- 错题本：错题自动汇聚归并，高频优先，可标记掌握
- 成长轨迹：历次分数曲线与各维度趋势
- PDF 报告导出

## 技术栈

| 层 | 选型 |
| --- | --- |
| GUI | PySide6（Qt 6），qasync 桥接 asyncio |
| 数据 | SQLAlchemy 2.0 async + aiosqlite（WAL 模式） |
| 实时语音 | WebSocket，OpenAI Realtime 风格协议 |
| 音频 | sounddevice + numpy（16 kHz 采集 / 24 kHz 播放） |
| 文档解析 | pdfplumber、python-docx |
| 密钥 | 系统 keyring（不落明文） |
| 打包 | PyInstaller |

架构分层：`core`（配置/事件/类型）→ `domain`（领域模型）→ `data`（持久层）→ `llm`（供应商抽象）→ `realtime`（语音链路）→ `agents`（各职能 Agent）→ `orchestration`（编排引擎）→ `ui`（视图层）。后端不依赖 Qt。

## 运行

需要 Python 3.12+ 与 [uv](https://docs.astral.sh/uv/)。

```bash
uv sync
uv run interviewer
```

打包为 Windows 可执行文件：

```bash
uv run pyinstaller interviewer.spec --noconfirm
```

产物在 `dist/Interviewer/`。

> 可执行文件名必须是 ASCII。中文文件名会让 PyInstaller 引导器在 CRT 层触发 `0xC0000409` 崩溃（目录名含中文没问题）。

## 模型配置

支持任意 OpenAI 兼容接口，在设置页按角色分别绑定。四个角色：导演（decide 下一步）、分析（复盘评分）、辅助（提词/STAR）、守卫（防漂移）。

**最省事**：只注册阿里云百炼一个 Key。实时语音必须来自这里，同时它也能供四个文本角色使用。

**效果最好**：百炼 + DeepSeek 两个 Key。

| 角色 | 推荐 | 理由 |
| --- | --- | --- |
| 实时语音 | 百炼 `qwen3.5-omni-realtime` | 语义 VAD 能区分"嗯嗯"附和与真插话，这对打断体验是决定性的；多音色让不同人设听得出区别 |
| 导演 / 复盘 | DeepSeek `deepseek-chat` | 长上下文、成本低，复盘质量更好 |
| 提词 / 守卫 | 百炼 `qwen-flash` | 这两个角色在延迟敏感链路上，要快 |

Key 存入系统凭据管理器，不写入配置文件。

## 隐私

- 所有数据存本地 SQLite（`%LOCALAPPDATA%/Interviewer/`），不上传
- 摄像头画面仅本地渲染，不经网络
- 音频需要发送到语音服务商才能对话，这是功能必需
- 简历含个人信息，请自行评估后再上传

## 已知问题

- 未经真实 API 端到端验证，长时面试的稳定性待观察
- 扬声器模式下回声抑制依赖互相关门控，强烈建议戴耳机
- 实时语音按时长计费，一场 30 分钟面试的语音开销是主要成本项
- 摄像头设备兼容性未广泛测试
